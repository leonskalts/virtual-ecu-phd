# Candidate 2 preregistered development protocol

This is DEVELOPMENT / TUNING DATA, never final holdout. Candidate 1 is frozen and is never retuned. This protocol is written before simulation execution; its hash, study hash, runtime source hashes, duplicate audit and split counts are saved before TRAIN.

1140 distinct physical configurations: 900 injected (180 per origin) and 240 benign. Profiles, onset times, severity combinations and split seed differ from Candidate 1. Group all variants of origin/model/behavior together; benign variants stay with their profile template. Stratify by origin with SHA256(17092027:group), assigning ceil(30% of groups) to development-validation. Audit semantic duplicates before any execution, including ignored permanent durations and severity-less deadline/fan settings. Compare physical signatures using profile bytes with Candidate 1 validation. Fixed injector seed 1 is not an independent stochastic replicate.

Eight detection configurations: threshold .50/.65, persistence 1/2, temporal retention .60/.80. Shared fixed origin reliabilities .9/.6, anomaly reliability 1, origin ignorance limit .5, suspect threshold .35. For each configuration, execute propagation on (.1) and off (0), capped reliability and 3000 ms window. On TRAIN only, sweep origin threshold .55/.70/.85 and margin .15/.30. All readouts use the actual origin score at the first post-injection alarm; changing localization never changes alarm state. This yields 96 documented readout/propagation choices, not 96 independent simulations.

First select the detection/readout operating point with propagation OFF: lexicographically minimize benign false-alarm runs, silent plant propagation runs, negative macro detection coverage, wrong non-UNKNOWN origins at first alarm, negative correct origins at first alarm, median detection latency, detection index, origin threshold, origin margin. Rewarding correct localization after wrong localization prevents arbitrary confidence guessing. Compare propagation ON at this exact point: retain it only if correct localization increases and wrong localization does not. Otherwise select zero and report propagation as an unsupported optional experiment. No per-origin thresholds or validation-driven choices.

Weighted Sum uses the same six raw available channel strengths and the same TRAIN rows: two global weight vectors (uniform and .2/.2/.2/.1/.2/.1) times thresholds .04/.06/.08/.10/.14/.18, one sample persistence. Minimize TRAIN benign false alarms, silent plant runs, negative macro coverage, median latency, then index. Freeze both configurations and write selection_record.json with validation_seen=false before any validation execution.

Run validation once with frozen operating points. Compare Candidate 2, frozen Candidate 1, OR (.5), calibrated Weighted Sum, matched-threshold Plain DS, existing Hybrid and timing-only Timing Monitor. Report B0 Plain DS, B1 dual frame, B2 origin reliability, B3 propagation, B4 temporal. B0→B1 changes both frame and positive-evidence policy; a supplemental single-frame positive baseline separates those effects. Detection reliability .9 and origin reliability removal are separate controls. B3/B4 retain .1 for controlled ablation even if the selected primary configuration disables propagation; distinguish them explicitly.

Raw physics and runtime observations are shared within each run; all methods execute online in isolated C states. Injected origin and onset are evaluation metadata only. A preexisting alarm is not credited at injection: detection requires a new rising alarm edge at/after onset. Report pre-injection alarm runs. Fault-free reference deviations score control/actuator/plant manifestations only after simulation. No detector reads them.

Localization primary endpoint is first alarm. UNKNOWN and missed alarms are distinct confusion categories. Report coverage, accuracy conditional on localization, wrong-localization count and rate, UNKNOWN, macro metrics, and first subsequent correct localization before plant. TRAIN later-localization times are omitted when a changed offline readout makes them invalid; validation uses the exact selected readout. Uncertainty distributions use per-run means (not pooled pseudo-independent samples). Selective curves are TRAIN-only; validation gets exactly one fixed operating point.

A possible second-candidate freeze requires a documented Pareto tradeoff, successful isolation/regression/replay/preservation checks and no evidence overwrites. No arbitrary recall threshold, no automatic replacement of Candidate 1. Even a frozen development candidate is not final validation. Host timing is measured wall time, never embedded WCET. No final holdout is created or examined.
