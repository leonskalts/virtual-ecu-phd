# Final cross-layer research configuration

Accepted scientific implementation: `0da05cc` (v5). V6 audits and presents this
implementation; it adds no experiment matrix, detector, runtime rule or physics.
The machine manifest is generated by `final_evidence.final_configuration()` into
`results/cross_layer_safety_v6/manifests/final_configuration.json`. The final study
index is `studies/cross_layer_final_paper_study.yaml`; the accompanying evidence lock
pins source/configuration and accepted artifact hashes before v6 integration.

The generator imports the frozen timing manifest, reads the accepted YAML hazard
mapping and parses the applicable numeric macros from `include/config.h`, checking
agreement. Values are not maintained as a separate v6 set of runtime constants.
The accepted values are P=D=100 ms; age evidence >P+D; repeated severity after three
violating observation periods in the half-open trailing 10P; critical absence >=3P.
Graded escalation uses >=5P age or continuous qualified communication evidence.
Warning/critical are 108/115 °C, critical exposure 1,000 ms, experimental FTTI
5,000 ms, and containment hold 1,000 ms. These values are a readable description
of the referenced sources, not independently selectable v6 thresholds.

The legacy CLI and single-run GUI retain their timing-monitor-disabled default for
compatibility. The *recommended research configuration* explicitly selects combined
observe-only timing monitoring. “Observe-only action” does not disable existing
legacy safety/diagnostic behavior; it makes no new runtime policy request. Neither
this recommendation nor the graded experimental arm is a deployment recommendation.

Non-injection scheduler workload containment/FTTI is N/A under the existing legacy
contract. Policy comparisons preserve fixed eligibility from the paired no-action
actuator/plant consequence cohort. Detection, intervention and containment are not
substitutes for one another. Missing endpoints and empty hazard cohorts stay N/A.

## Runtime and evaluation boundary

The new timing monitor and graded policy accept runtime telemetry; they do not
consume fault identity, a benign/overload label, reference trajectories or future
hazards. The communication policy depends on existing alarm evidence. The whole
platform is not production-signal isolated: legacy detector residuals use true plant
state, and diagnostics/bookkeeping retain scenario information. See the canonical
[observability boundary](detector_observability_boundary.md) and
[architecture](cross_layer_platform_architecture.md).

The plant and timing monitor retain 100 ms sampling. Workload events model CPU
occupancy at 1 ms using held macrostep data. There is no measured ECU WCET, full
vehicle model, HIL validation or certified safety lifecycle. Trusted supervision is
assumed. Designed correlated scenarios limit population interpretation of Wilson
intervals. The final holdout has no hazards, so generalized hazard prevention is
unestablished. These limitations are preserved in the generated limitations register.
